> 제품 PRD의 설계와 홈페이지 인터뷰를 근거로 작성했다. 실제 프로그램, 서버, 상담 도구와 통계 서비스의 처리 사실은 아직 대조하지 않았다. 대괄호·확인 필요 항목을 채우고 실제 처리와 일치하도록 수정한 후 게시한다.

## 1. 적용 범위와 핵심 안내

[운영 주체의 정확한 명칭, 이하 “운영자”]는 BLOW 홈페이지, 프로그램 계정·이용권 관리 및 상담 과정에서 처리하는 개인정보에 관해 이 방침으로 안내한다.

BLOW는 브랜드 블로그 글·이미지의 준비와 네이버 임시저장을 돕는 프로그램이다. 작성 결과의 최종 검토와 발행은 이용자가 직접 한다.

데이터를 이해할 때 다음 세 범위를 구분해야 한다.

| 구분 | 제품 PRD·인터뷰 기준 |
| --- | --- |
| BLOW 서버 | 계정·인증·이용권·등록 기기·입금 확인·동의 이력 및 필요한 보안 기록 등 최소 정보 |
| 이용자 PC | API 키·네이버 세션·브랜드 프로필·작성 내용·참고자료·생성 이미지 등을 관리하는 설계 |
| 외부 서비스 | 생성 요청은 OpenAI에, 네이버 편집기 입력·임시저장은 네이버에 필요한 정보를 전달 |

“BLOW 서버에 글이나 API 키를 저장하지 않는다”는 설계는 어떤 외부 사업자에게도 전송되지 않는다는 뜻이 아니다. 서버 저장 여부와 외부 전송·처리는 구분해서 안내한다.

> 공개 전 확인: 다음 조항의 설계 내용이 실제 출시 버전과 일치하는지 검증한다. 확인되지 않은 상태로 “미수집”, “미저장”, “암호화”, “즉시 삭제”를 확정 문구로 게시하지 않는다.

## 2. 처리 목적·항목·보유기간

아래는 공개 본문을 완성하기 위한 기준표다. 처리 근거는 목적별로 확정하며, 방침을 읽거나 약관에 동의했다는 이유만으로 모든 처리에 동의했다고 보지 않는다. 동의가 필요한 항목은 별도 고지·동의 절차를 갖춘다.

| 상황 | 목적 | 예정 또는 확인할 항목 | 보유기간 | 처리 근거 확인 |
| --- | --- | --- | --- | --- |
| 프로그램 회원가입·인증 | 계정 생성·본인 계정 확인·로그인 | 이메일, 인증 식별자, 인증 시스템이 관리하는 비밀번호 해시 등 | 탈퇴 또는 목적 달성 시까지. 별도 법정 보존 항목 제외 | 계약 이행 등 적용 근거 확인 |
| 이용권·기기 등록 | 사용 권한·기간과 등록 PC 관리 | 계정 식별자, 승인·만료 정보, 등록 기기의 해시 식별값, 필요한 변경 이력 | 계정·계약 목적 달성까지, 세부 삭제 주기 확인 | 계약 이행 등 적용 근거 확인 |
| 입금·환불 | 결제 확인·기간 부여·환급·증빙 | 입금자명, 금액, 입금일, 연결 계정, 필요한 거래 식별 정보. 환불 시 예금주·은행·계좌번호 | 법정 보존 대상은 해당 기간, 불필요한 추가 사본은 목적 달성 후 삭제 | 계약 이행·법정 의무의 범위 확인 |
| 전화·카카오 상담 | 문의 응대·장애 해결·분쟁 처리 | 상담자가 제공한 연락처·계정 정보·문의 내용·필요한 처리 이력 | 일반 문의 [기간 확정], 소비자 불만·분쟁 기록은 해당 법정 기간 | 계약 관련 처리 또는 필요한 별도 근거 확인 |
| 최소 보안 로그 | 계정 보호·오남용 대응 | 실제 기록되는 접속·인증 실패·관리자 조작 기록 [정확한 항목 확인] | [기간 확정] | 필요성과 적용 근거 확인 |
| 홈페이지 접속 | 페이지·파일 제공과 보안 | 호스팅이 처리하는 IP·요청 시각·브라우저 정보 등 [실제 항목 확인] | [제공업체 설정 후 확정] | 실제 처리 목적·근거 확인 |
| 홈페이지 기본 통계 | 방문 수·유입 경로·기기 구분 확인 | [통계 제공업체의 실제 수집 항목, 식별자·IP 처리 포함] | [기간 확정] | 쿠키·행태정보·국외 처리 등 적용 요건 확인 |

기기 해시값이 있다는 이유만으로 익명 정보라고 단정하지 않는다. 계정과 연결되는 정보는 개인정보 해당 여부를 함께 검토한다. 비밀번호 해시는 인증 시스템이 관리하는 값이며 운영자가 이용자의 원문 비밀번호를 볼 수 있다는 뜻이 아니다.

상담을 이유로 비밀번호, 전체 API 키 또는 불필요한 신분증 사본을 요구하지 않는다. 전화 통화 자동 녹음은 이번 홈페이지 기획에 포함하지 않았다. 도입하려면 실제 처리 사실과 필요한 고지·근거를 별도로 정해야 한다.

## 3. 법령에 따라 보관할 수 있는 거래 기록

관계 법령이 적용되는 거래 기록은 목적 달성이나 탈퇴 이후에도 해당 기간 동안 필요한 범위에서 분리해 보관하고 기간이 끝나면 파기한다.

| 기록 | 보존기간 |
| --- | --- |
| 표시·광고에 관한 기록 | 6개월 |
| 계약 또는 청약철회 등에 관한 기록 | 5년 |
| 대금 결제 및 재화 등의 공급에 관한 기록 | 5년 |
| 소비자 불만 또는 분쟁 처리에 관한 기록 | 3년 |

이는 모든 계정 정보나 상담 내용을 일괄 5년 보관한다는 뜻이 아니다. 실제 거래에 적용되는 기록과 최소 항목을 구분한다. [전자상거래법 시행령 제6조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0006&lsiSeq=269055&urlMode=lsScJoRltInfoR)

다음은 원본 제품 PRD의 로컬 처리 설계이며 출시 구현과 대조한 뒤 공개 문구로 확정한다.

| 정보 | 설계상 처리·보관 |

API 키·세션 보호와 모든 로컬 콘텐츠의 암호화는 다르다. 원본 PRD는 모든 로컬 글·파일을 완전 암호화한다고 정하지 않았다. “모든 데이터가 암호화돼 누구도 볼 수 없다”라고 안내하지 않는다.

실패한 작업의 파일, 캐시, 임시파일, 삭제 요청 후 남는 백업과 로그도 확인 대상이다. 프로그램 제거만으로 네이버 게시물이나 외부 서비스의 기록까지 삭제된다고 설명하지 않는다. 다른 PC로 자동 백업·복구하는 서비스가 있는 것처럼 안내하지 않는다.

## 5. 생성형 AI 및 네이버로 전달되는 정보

### 5.1 OpenAI

이용자가 생성 기능을 실행하면 요청에 필요한 브랜드 정보, 주제, 키워드, 참고자료의 내용·이미지와 설정 등이 개인 OpenAI API를 통해 전달될 수 있다. 실제 API 종류와 파일 처리 방식에 따라 전달 항목이 달라질 수 있으므로 출시 구현의 요청 내용을 확인해 구체적으로 기재한다.

확정해야 할 항목:

- 처리하는 OpenAI 계약 주체와 연락처.
- 실제 전송 항목, API 종류, 파일 업로드·저장 여부와 삭제 방식.
- 처리 국가, 전송 시점·방법, 보유기간과 재위탁 등.
- 운영자·이용자·OpenAI의 관계에 따른 처리위탁·제3자 제공·국외 이전의 적용 구조 및 법적 근거.
- AI 학습 이용 여부, 이를 변경할 수 있는 설정과 권리 행사 방법.

개인 API를 사용한다는 이유만으로 운영자의 검토 의무가 모두 사라진다고 단정하지 않는다. BLOW 서버 미저장이나 특정 API 옵션만으로 외부 사업자의 보유기간이 항상 0일이라고 설명하지 않는다.

### 5.2 네이버

편집기 입력·임시저장 과정에서 글·이미지 등 이용자가 저장하도록 한 정보가 네이버에 전달된다. 로그인과 추가 인증은 네이버가 제공하는 절차를 따른다. 네이버 계정과 저장된 글의 보관·삭제는 이용자의 네이버 이용과 해당 서비스 정책의 영향을 받는다.

### 5.3 AI 결과에 대한 문의

생성 결과에 개인정보가 부적절하게 포함되거나 권리 침해가 의심되면 010-5768-1840 또는 준비된 카카오 채널로 문의할 수 있다. 운영자는 필요한 범위에서 발생 상황을 확인하고 BLOW의 처리 범위 안에서 조치한다. 신고 과정에서 불필요한 개인정보나 API 키를 재전송하지 않도록 안내한다.

PC 내부 처리와 서버 처리의 구분, 생성형 AI 입력·출력 및 학습 관련 설명을 실제 구조에 맞게 작성하는 데 참고한 공식 안내: [개인정보보호위원회 2026년 개인정보 처리방침 작성지침 개정](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&nttId=12021)

## 6. 처리위탁·제3자 제공

운영자는 실제 외부 처리 구조에 맞추어 다음 표를 확정한다. 아래 서비스명은 법적 계약 주체의 확정 명칭이 아니며, 모두 동일하게 수탁자나 제3자 수령자로 단정하지 않는다.

| 서비스 | 제품 PRD 또는 계획상 역할 | 공개 전에 확인할 사항 |
| --- | --- | --- |
| Supabase | 계정 인증과 최소 계정·이용권 정보 관리, 서울 리전 설계 | 계약 주체, 위탁 업무·항목, 재위탁, 로그·백업·원격 접근, 기간 |
| Amazon SES | 인증 이메일 발송, 서울 리전 설계 | 계약 주체, 이메일·발송 기록 처리, 위탁·재위탁와 기간 |
| OpenAI | 개인 API를 통한 콘텐츠 생성 | 제5절의 전송·계약·처리 역할 및 국외 이전 사항 |

| 카카오 채널 | 상담 연락 | 실제 채널, 수집 항목, 상담 이력·보관, 각 주체의 역할 |

| 방문 통계 제공업체 | 기본 통계 | 업체 미정. IP·쿠키·식별자·보유기간·처리 국가 확인 |

서울 리전을 선택했다는 이유만으로 모든 데이터의 국외 접근·이전 가능성이 없다고 단정하지 않는다.

업무 위탁이 있으면 필요한 계약·관리·감독과 공개를 진행한다. 제3자 제공이 있으면 수령자, 목적, 항목과 보유기간 등을 구체적으로 고지하고 동의 또는 다른 적법한 근거를 확인한다. 검증되지 않은 상태에서 “제3자 제공 없음”으로 확정하지 않는다.

## 7. 국외 이전

국외 이전에 해당하는 처리 사실이 있는 경우 아래 정보를 외부 사업자별로 확정하여 공개하고, 필요한 고지·동의 또는 다른 법적 근거를 갖춘다.

| 필수 확인 대상 | 기재할 내용 |
| --- | --- |
| 이전받는 자 | 정확한 법적 명칭과 연락처 |
| 국가 | 실제 저장·처리·접근 국가 |
| 이전 항목 | 실제 개인정보 항목 |
| 시기·방법 | 요청 시점, 네트워크 전송 등 실제 방식 |
| 목적·기간 | 처리 목적과 보유·이용기간 |
| 법적 근거 | 동의 또는 그 밖의 적용 근거 |
| 거부 방법·영향 | 선택권이 있는 범위, 거부 방법과 이용에 미치는 구체적 영향 |

현재 표를 채울 실제 계약·설정 검증이 완료되지 않았다. 표를 비운 채 최종 방침으로 게시하거나 국외 이전이 전혀 없다고 선언하지 않는다.

## 8. 홈페이지 통계와 자동 수집

홈페이지에는 방문 수, 유입 경로, 기기 구분을 확인하는 기본 통계를 도입할 계획이다. 상담·전화·다운로드 클릭 이벤트, 방문자 화면 녹화·행동 재생 및 광고 리타기팅은 계획에 포함하지 않는다.

통계 업체가 확정되면 다음 사항을 구체적으로 기재한다.

- 처리 항목과 수집 방식.
- 쿠키·브라우저 저장소·식별자 사용 여부.
- IP 처리 방식과 보유기간.
- 제공자와 처리 국가.
- 거부·차단 방법 및 동의가 필요한 경우의 절차.

선택 전에는 분석 스크립트를 삽입하지 않는다. 외부 링크를 열었을 때 해당 서비스에서 수행하는 처리는 구분해서 안내한다. 단순히 버튼 클릭을 자체 추적하지 않는다는 이유로 호스팅·외부 서비스에서도 아무 기록이 남지 않는다고 설명하지 않는다.

## 10. 파기 절차와 방법

운영자는 처리 목적 달성 또는 보유기간 종료 후 법령상 보존 사유가 없는 개인정보를 파기한다. 보존이 필요한 정보는 다른 목적에 사용하지 않도록 분리·제한한다.

전자 파일은 복구·재생이 어렵도록 적절한 방법으로 삭제하고, 종이 문서가 있다면 분쇄 등으로 폐기한다. 백업·로그의 삭제 주기와 접근 제한은 실제 시스템 운영 기준에 맞춰 별도로 확정한다.

> 공개 전 확인: 계정 탈퇴, 이용권 만료, 상담 종료와 환불 처리 각각의 삭제 대상·기한을 구분한다. 구현이 확인되지 않은 “요청 즉시 모든 데이터 완전 삭제”를 약속하지 않는다.
